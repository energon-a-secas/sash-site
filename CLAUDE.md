# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make serve                              # http://localhost:8884
make kill                               # stop the server on 8884

npx convex dev --once                   # push convex/ to the dev deployment
npx convex deploy                       # production, for anything the public touches
npx convex run seed:ensureNeorgonTemplates
npm test                                # enum, rate-limit and seed-idempotence checks
node convex/tests/contract-shapes.test.mjs   # not in `npm test`; needs a live deployment
```

`npm test` runs three of the four test files. `contract-shapes.test.mjs` calls
every public query and diffs the answer against CONTRACTS.md as amended, which
is what would have caught the four amendments (A19, A30, A41, A45) that exist
because a type block disagreed with its own function. It is not wired in because
it needs a deployment to talk to: with none it exits **2**, so "nothing was
compared" can never read as a pass. A48 and A49 make it a release gate.

No build step. Pages are static HTML, the client is ES modules, and the Convex
client comes from `https://esm.sh/convex@1.21.0/browser`.

## Architecture

**Eight pages in the contract, nine HTML files.** C13.1 names eight
(`index`, `u`, `badge`, `claim`, `embed`, `import`, `send`, `policy`); `404.html`
is the ninth and is in no contract, which is why the two counts in this file
used to disagree. The CSP note below counts HTML files across both sites and
gets thirteen: nine here plus Enamel's four. Both numbers are right, they count
different things.

**Four of the nine take a query parameter, and none takes a path.** GitHub Pages
cannot rewrite paths, so an address that carries a value is
`page.html?param=value`: `u.html?h=<handle>`, `badge.html?id=<publicId>`,
`claim.html?t=<token>`, `embed.html?h=<handle>`. The other five are addressed
plainly. The `404.html` router trick was rejected: it returns HTTP 404 for every
pretty URL, which breaks link previews and indexing on pages whose whole purpose
is being shared.

**One entry point for two pages, one module each for the other five.**
`js/app.js` reads `body[data-page]` and calls `initWallet()` (index.html) or
`initProfile()` (u.html). Every listener on both pages is in `js/events.js`; the
page controllers export the actions it calls. `badge.html`, `claim.html`,
`embed.html`, `import.html` and `send.html` each load the `js/` module of the
same name, and `policy.html` and `404.html` load only `js/frame.js`. There is no
inline `onclick` in this project and nothing is put on `window`.

**The award grid is not in this repo's own code.** `js/insignia/wallet.js` is the
vendored kit and owns `renderAwardCard`, `renderAwardGrid` and the profile
poster. `js/wallet.js` is this site's page wiring. **Two different files, same
basename**: the kit one is never edited here, it is regenerated by
`packages/neorgon-ui/sync-insignia.sh`. Same rule for `js/insignia/*`,
`js/neorgon-*.js` (the header, footer, DOM, avatar, beacon and auth kits, each
with its own `sync-*.sh`) and `js/convex.js` (which the backend owns, because it
is the mirror of the function surface). There is no `js/vendor/` any more.

**Sign-in is the Neorgon Auth Kit, and this site owns no sign-in markup.**
`js/neorgon-auth.js`, `js/neorgon-auth-sites.js` (generated) and
`css/neorgon-auth.css` are vendored by `packages/neorgon-ui/sync-auth.sh`. The
kit paints the `.neo-auth` slot in the header and hosts Clerk's form in its own
`<dialog>`; `startAuth` in `js/state.js` calls `NeoAuth.start({ convex })` and
mirrors the settled `signedIn` and `label` into `state`. A page that needs an
account asks with `NeoAuth.requireSignIn({ reason })`, and the hero button on
`index.html` opens the dialog with `NeoAuth.openSignIn`. The auth sheet that sat
under the header (`#authPanel`, `#authToggle`, `#authError`) went with
`js/vendor/neorgon-auth.js` on 2026-09-14, and `sync-auth.sh --check` (smoke
check 13) fails on any of them coming back.

**The site adds controls to a kit card rather than drawing its own.**
`render.js` calls `renderAwardGrid(list, { groupBy: 'none' })` per section and
appends a `.sash-card-actions` row to each returned card, matching cards to
awards by index and checking the counts agree first. Grouping into the four
wallet groups is this site's job; drawing is the kit's.

**Nothing is drawn without provenance.** `renderSvg` throws a `TypeError`
without a valid provenance object, so there is no path from a design to pixels
that skips the strip naming the origin, the issuing handle and the verify URL.

**Do not write `escHtml` here. It exists.** `js/neorgon-dom.js` is the Neorgon
DOM Kit, vendored by `packages/neorgon-ui/sync-dom.sh`, and it owns `escHtml`,
`showToast`, `debounce`, `copyText`, `downloadBlob` and the rest. C15 A53: this
site had written its own `escHtml` escaping four characters where the kit's
escapes five, and the kit exists because 52 sites did the same thing eleven
different ways, five of them injectable in attribute position. `js/utils.js`
holds only what is about badges, plus `el` and `$`, which the kit does not
carry. **`$` is not Enamel's `$`**: this one caches permanently because this
site fills a shell it never replaces, and that difference is deliberate.

**One date format, and it belongs to the kit.** `formatDate` in
`js/insignia/certificate.js` renders `9 September 2026` and is the only date
formatter either site may use (A54). `js/utils.js` wraps it twice and no more:
`stamp` adds a UTC time for the two things that happen later today rather than
one day, and `humanMs` says a duration in words. Enamel holds byte-identical
copies of both. A `toLocaleDateString` anywhere in this repo is a regression.

## Key state

`state` in `js/state.js`, one object shared by every module:

- `profile`: `profiles:me`, the signed-in wallet only. Carries `showcase`, the ordered list of pinned award public ids.
- `publicProfile`: `profiles:byHandle`, the public page only. Carries `showcase` since C15 A39. `u.html` treats an absent or empty list as "no showcase" rather than an error, so it renders the same either way.
- `awards`: `OwnAward[]` on index.html, `PublicAward[]` on u.html.
- `allAwards`: u.html only, the ungrouped wall from the first load, so the showcase survives a chip that narrows `awards` to one group.
- `signedIn`, `authLabel`: the Auth Kit's settled state, mirrored by `startAuth`. Nothing else about the session is kept here; the kit holds it.
- `group`: the chip filter, one of C7.22's `all | neorgon | community | recognition | imported`.
- `showHidden`: the only value persisted, under `sash-prefs` in `localStorage`. Nothing about a person is stored in the browser.

## Gotchas

**`https://sash.neorgon.com/ob/keys/1.json` must never move, never 404 and never
change content.** If it does, every badge Sash has ever exported becomes
unverifiable at once. That is a stronger uptime commitment than the fleet makes
about anything else. Key rotation means publishing `2.json` and keeping `1.json`
forever.

C9.2 requires that paragraph in this file, verbatim, under this heading. It is
in `convex/README.md` too, and `convex/README.md` does not auto-load. C15 A52:
the campaign's strongest one-way door was the one thing missing from the only
file a future session is guaranteed to read.

What breaks, and how quietly: every signed credential ships `kid` and never
`jwk` (C9.2), so a verifier resolves that URL and nothing else. Move the file,
rename the directory, or let the Pages build drop it, and every badge Sash ever
exported starts failing verification, in somebody else's tool, with no error
anywhere in this repo and no way to reach a holder who already downloaded the
file. There is no revocation for a key that stopped existing.

The public half is `ob/keys/1.json`, committed here. The private half is
`OB_SIGNING_KEY` on the **production** deployment (`youthful-oyster-436`, the
URL every shipped page names in its `neo-convex-url` meta), set 2026-09-10 and
never printed anywhere. Check that the two halves match with
`npx convex env get --prod OB_SIGNING_KEY | shasum`, never with `env list`,
which prints every line of a multi-line value into the terminal. The dev
deployment named by `.env.local` holds a throwaway key that does **not** match
`1.json`, so a badge exported against dev verifies nowhere, and that is
expected. `convex/ob.ts:259`
answers `{ ok:false, code:"no-key" }` without it, which is the C9.3 degraded
export: the PNG still downloads, unsigned, and the page says so. That is the
designed behaviour, not a warning that the key is missing, so a production
deploy with no key set is a site that quietly stops issuing verifiable badges
while every button still works.

**Enamel has no `convex/` folder, and that is deliberate.** `sash.neorgon.com`
and `enamel.neorgon.com` are two origins over **one** Convex deployment, which
lives here and nowhere else. Enamel points a `ConvexHttpClient` at this
deployment's URL and calls the same functions. Nothing else in the fleet does
this, so the next operator will go looking for a second `convex/` folder and not
find one. Sash owns it because Sash is the system of record: `profiles`,
`awards`, `claims` and `kudos` live here, and this origin is printed on every
badge and inside every signed credential.

**Clerk refuses a production key on `localhost`.** The key is `pk_live_…` for
`clerk.neorgon.com`, and its API rejects any origin that is not the production
domain: the console says *Production Keys are only allowed for domain
"neorgon.com"*. So `make serve` can exercise every signed-out page and none of
the signed-in ones. To drive the wallet locally, serve the folder over TLS and
map the hostname, for example a local HTTPS server on 9443 plus Chromium's
`--host-resolver-rules=MAP sash.neorgon.com 127.0.0.1:9443`. Sign-**up** still
will not complete: it is behind an interactive Cloudflare Turnstile that refuses
an automated browser. Sign-in with an existing account does work. Since the Auth
Kit (2026-09-14) the refusal is reported inside the kit's dialog when somebody
asks to sign in, never thrown at the page, and the kit also honours
`localStorage["neo-auth:dev-key"]` with a `pk_test_` key on localhost only; the
page's CSP still has to be loosened locally before that instance can load.

**The deployment URL is a meta tag, not a constant.**
`<meta name="neo-convex-url">` on every page of both sites, and `js/convex.js`
throws on load if it is missing or malformed. Changing deployment is one edit
per page and a `grep` to prove it, rather than a code review.

**The showcase is drawn twice on `u.html`, and that is deliberate.** A39 gave
`PublicProfile` a `showcase`, so the pin order a person sets on their wallet is
finally visible to a stranger. `js/profile.js` uses it in two places: a strip
above the wall, mirroring what the owner arranges on `index.html`, and a stable
sort of the wall itself, so a pinned badge still leads its own group after a
chip narrows the view. `resolveShowcase` in `js/render.js` is the one place an
id becomes an award, and it skips an id that no longer resolves rather than
drawing a hole.

**Framing cannot be prevented here, so it is handled instead.** C5.3 froze a
frame buster (`window.top.location = window.self.location`); measured from a
real cross-origin host it is refused for want of user activation in Chromium,
Firefox and WebKit alike, throws, and leaves the page framed. C15 A36 replaced
it. `frame-ancestors` is the directive that would work, it is ignored in a
`<meta>` CSP by specification, and GitHub Pages sets no response headers.

Three pieces, and all three have to be there: the inline guard in the `<head>`
sets `data-framed` on `<html>` and navigates nowhere, `css/frame.css` takes the
page out of view, and `js/frame.js` puts a notice in its place. Every entry
module imports `framed` and returns before it mounts anything, which is what
keeps sign-in and every write control off a framed page. **Do not put the buster
back**, and do not add the guard to `sash-site/embed.html`: being framed is that
page's whole purpose.

**The CSP is one string on thirteen HTML files and must stay that way.** Nine
here, four in Enamel. C13.3 plus amendments A37, A38 and A50. A50 is the newest
and the easiest to drop when copying the string: `frame-src` gained
`https://sash.neorgon.com` and `https://enamel.neorgon.com`, so either site can
embed the other's badge wall. Without them our own policy blocks it.

It allows the header kit's own analytics
(`static.cloudflareinsights.com`, `gc.zgo.at`, `cloudflareinsights.com`,
`neorgon.goatcounter.com`), which the frozen policy did not, and `https:` in
`img-src` for imported artwork nobody can enumerate. Two entries look
redundant and are not: **`https://fonts.googleapis.com` and
`https://fonts.gstatic.com` in `connect-src`**, without which the first fetch of
every export throws, and **`data:` in `font-src`** for the inlined face. The
policy is byte-identical on all twelve non-embed pages of both sites; only
`embed.html` differs, by dropping the Clerk entries and the analytics it never
loads. **Editing it on one page is how a fleet ends up with three policies.**

The reason this went unnoticed for a whole campaign: the kit gates analytics on
`location.hostname`, so nothing is injected on `localhost`. To exercise it,
serve the folder and map the hostname, for example Chromium's
`--host-resolver-rules=MAP sash.neorgon.com 127.0.0.1:8884`.

**An imported award is null in five places.** `origin` is `"imported"` and
`category`, `sphere`, `issuerHandle`, `versionN` and `design` are all `null`.
`award.issuerHandle.toUpperCase()` throws on every imported credential, in the
render path. Test `source === 'import' || origin === 'imported'` first and render
nothing rather than an empty string.

**A handle is claimed once and never changes.** It is printed into every
rendered artefact and sits inside every signed credential, so a rename would
have to reach files that have already been downloaded. `profiles:claimHandle` on
a profile that has one returns `already-set`.

**Handles go to 30 characters and the badge provenance strip now fits them.**
Fixed, A33 by way of A51, and recorded here because the shape of the fix
constrains the next change to that strip. At the maximum length the top line
measured 638.63 user units on a 484 unit plate, and a `COMMUNITY BADGE` label
plus a 30 character handle exported as `UNITY BADGE @abcdefghij-klmnopqrst-uv`:
a handle that resolves to no profile at all, printed onto the artefact by the
C11.1 provenance control. `packages/neorgon-ui/insignia/render.js` drew
`lines.top` at a fixed `size: 20` with none of the fit logic `lines.bottom` has
carried since A24; it now takes the same `textLength` branch, shrinking size and
tracking together down to a floor and narrowing the glyphs past it. **The string
is never shortened**, which is the point: a cut handle is a wrong answer where a
reader expects the answer, and that is the defect, not the fix for it. The
branch only engages when the line exceeds the plate, so a badge that already fit
is untouched. Certificates were never affected; that plate is 1,548 wide.

## Contracts

`docs/delivery/CONTRACTS.md` in the monorepo is the frozen source for the design
document (C1), the Convex function surface (C2), ids and handles (C4), the embed
(C5), exports (C6), the enums (C7), the deployment topology (C8), Open Badges
(C9), provenance (C11), the page inventory and the CSP (C13). Section C15 holds
every amendment made to them after the freeze. Read C15 before trusting a type
block in the body of the file: A49 corrected **four** of them in place
(`PublicProfile` missing `showcase`, `ClaimPreview` missing `defaultValidityMs`,
`PublicAward` typing four fields non-nullable, and C7.2 listing two `origin`
members where both enum files carry three), and a fifth error was inside the
amendment written to stop the pattern. `convex/tests/contract-shapes.test.mjs`
is the machine that checks this, and it is the reason to run it rather than
re-read the file.
